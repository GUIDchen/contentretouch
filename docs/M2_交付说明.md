## 9. 清单与元数据库打通（本轮新增）

### 9.1 为什么需要

抖音清单文件里只有 id / 标题 / 点赞 / 封面，**没有作者**——所以界面按「作者/收藏夹」分类时，抖音条目全挤在「未标注」里。而作者数据其实已经在元数据库里（第 3 节的补采结果）。这一步就是把两者接上。

### 9.2 做法

| 环节 | 实现 |
| --- | --- |
| 导出 | library.mjs --export-preview-meta <out>/preview_meta.json，把「作品 id -> 作者/收藏夹/平台/点赞/发布日期/图片数/是否已下载」导成一份 JSON |
| 触发 | 「同步元数据库」任务（tools/library_sync.sh）在清洗之后自动导出，不需要额外操作 |
| 合并 | App 读清单时（preview::load）读同目录的 preview_meta.json：清单自带作者优先，没有就用库里的补，并给每条标注 authorSource（清单 / 元数据库） |
| 呈现 | 结果区统计里显示「作者来自元数据库 N 条」，被补过的分类标题旁标注「作者来自元数据库」 |

### 9.3 实测结果

| 清单 | 条数 | 有作者 | 其中来自元数据库 | 不同作者 |
| --- | --- | --- | --- | --- |
| 抖音收藏清单 | 2019 | 2007 | 2007 | 1892 位 |
| B站收藏清单 | 313 | 313 | 0（清单自带） | 238 位 |

也就是说：抖音清单现在能按 1892 位作者分类，剩下 12 条是库里也还没有作者的（多为此前判定失效的笔记）。

### 9.4 顺带修掉的一个数据坑（值得记）

旧清单用 serde 一读就报 `unexpected end of hex escape`，但 node 读同一份文件完全正常。根因是采集时为了防超长用了 `str.slice(0, 120)`：**JS 的 slice 按 UTF-16 码元切，会把一个 emoji 切成两半**，留下孤立的高代理项。JS 自己读写没感觉，Rust 的 serde_json 直接拒绝整份清单。

修法（已落到工具里）：

 - tools/lib/text.mjs 新增 safeSlice（按码点截断，不切断 emoji）、stripLoneSurrogates（清掉孤立代理项）、cleanText（两者合一）
 - 采集器写盘前统一清洗标题；下载器取到标题/作者后先清洗再拼路径与写台账；补采脚本的作者清洗也先过一遍
 - App 侧解析失败时给出可行动提示（说明常见原因是 emoji 被截断，建议重新采集或清洗清单）
 - 已存在的旧清单做了一次清洗（原件留在 /tmp/douyin_collected_v2.json.orig）

### 9.5 验证

| 验证项 | 方法 | 结果 |
| --- | --- | --- |
| 合并逻辑 | cargo test（author_filled_from_library_meta） | 通过：有作者的用清单的、缺的用库里的、来源标注正确 |
| 真实清单 | content-harvester --preview <清单> <输出目录> | 抖音：2007/2019 有作者，全部来自元数据库 |
| 文本清洗 | 四组用例（正常 emoji / 孤立高 / 孤立低 / 成对） | 孤立代理项被清掉，成对 emoji 保留 |

### 10.4 边界

 - 视频分支依赖 yt-dlp 能解析该链接；图文笔记本来就没有视频，会记为「无视频」而不是失败。抖音视频笔记尚未做大规模验证。

### 11.3 暂停 / 继续 / 取消

| 操作 | 实现 |
| --- | --- |
| 暂停 | 给子进程发 SIGSTOP（挂起但保留现场），任务状态变 paused |
| 继续 | 发 SIGCONT，从挂起点接着跑，状态回到 running |
| 取消 | 运行中直接杀进程；排队中直接从队列摘掉；暂停中的也能取消 |

自检实测：暂停后状态 paused、没有退出码（说明进程真的活着）、0.6 秒后仍是 paused；继续后回到 running；暂停中再取消也能成功。

### 11.4 下载不再来回跳浏览器，进度在 App 里看

 - 采集用的标签页改为后台创建（background: true）并去掉所有 Page.bringToFront，浏览器窗口不会再被反复切到前台。
 - 下载器每次操作都打印一行机器可读进度：PROGRESS {"title":...,"author":...,"images":9,"done":6,"index":7,"count":50}
 - App 解析这行，在进度卡片上显示：**正在下载 《标题》 · 作者 · 6/9 张 · 第 7/50 条**，并据此画进度条；日志里不再刷原始 JSON（替换成「（进度更新）」）。

### 11.6 边界

 - 暂停是挂起整个子进程（SIGSTOP），浏览器/网络连接会保持占用；长暂停期间不会自动超时，但也不释放资源。
 - 暂停中的任务仍占用并发名额（不会被新任务顶掉），继续后原地接着跑。
 - 「无视频」不算失败：图文笔记勾了视频时，会显示「视频 0（无视频 N）」而不是记失败。

### 12.5 边界

 - 小红书平台下的采集与下载仍不可用（未接入），但账号与下载内容的配置可以填，界面会明确提示。
 - 「选择文件夹」是系统原生对话框：在 App 里弹在 App 上，开发态（浏览器 mock）里不会真的弹（mock 直接返回一个假路径）。
 - 平台设置只存在内存里（切平台有效，关掉 App 会回到默认值）；要持久化需要再落一份配置文件。
