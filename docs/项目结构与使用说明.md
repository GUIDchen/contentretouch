# 项目结构与使用说明

> 说明当前工程有什么、放在哪、怎么用、怎么扩展。命令可直接复制执行。

## 1. 顶层结构

    dsh-xiutu/

    │   ├── 01_style/ 02_colored/ 03_retouched/   预留中间件目录

    │   ├── 06_variants/               B 日系冷调 / C 高级灰电影感 样式样本

    │   └── sign_and_notarize.sh       Developer ID 签名与公证（--check 可体检）
    ├── tools/login.mjs                账号登录助手：打开登录页 / 切登录方式 / 截二维码（不代填凭据）

    │   ├── cdp.mjs                    CDP 命令行小工具（薄壳：--cookies / --nav / --text / --shot）
    │   ├── collect.mjs                滚动默认收藏列表收集 note 链接
    │   ├── collect_folders.mjs        遍历收藏夹并求并集 -> /tmp/douyin_union.json
    │   ├── download.mjs               图集提取 + 下载（分片 / 续跑 / 重试 / --force）
    │   ├── make_retry.mjs             生成补漏清单（失败 + 张数不足）
    │   ├── make_index.mjs             manifest.csv -> index.html + summary.json
    │   ├── finalize.mjs               覆盖率统计 + 重复文件归入 _superseded/
    │   └── run_all.sh                 一键跑完（首轮 3 窗口 -> 重试 -> 索引）
    └── docs/                          ④ 本文档三件套

下载产物落在 ~/Downloads/douyin_favorites/（与代码分离，便于整体搬走）。

## 2. 三段工作流怎么跑

### 2.1 修图流水线

    # 0) 环境自检（不需要素材）
    python3 photo-style-pipeline/check_style.py --selftest
    python3 photo-style-pipeline/make_lut.py --selftest
    python3 photo-style-pipeline/make_params.py --selftest
    python3 photo-style-pipeline/s3_export_check.py --selftest

    # 1) 逐张自适应参数（按原片亮度与 p99 决定 gamma、提亮、是否走高光滚降）
    python3 photo-style-pipeline/make_params.py --dir 2604_wedding/00_RAW_readonly \
        --out 2604_wedding/_work/params.tsv

    # 2) Photoshop 批量修图（AppleScript 调 PS 执行 _work/batch.jsx）
    osascript -e 'set js to (read POSIX file "2604_wedding/_work/batch.jsx" as "utf8")' \
      -e 'tell application "Adobe Photoshop 2026" to do javascript js'

    # 3) 验收 + 重算报告
    python3 photo-style-pipeline/s3_export_check.py --dir 2604_wedding/04_master/psd --expect 8
    python3 2604_wedding/_work/report.py

注：AppleScript 读取脚本文件时需用 UTF-8 方式读取（实际命令使用 POSIX file 与 utf8 类）。

### 2.2 抖音收藏下载

    # 一次性：启动专用 Chrome（登录态与日常浏览器隔离）
    /Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
      --remote-debugging-port=9222 --user-data-dir="$HOME/.dsh/douyin-profile" \
      --disable-backgrounding-occluded-windows --disable-renderer-backgrounding \
      https://www.douyin.com/          # 首次需手机扫码 + 身份验证

    # 采集清单（默认列表 + 收藏夹）
    cd tools/douyin
    node collect.mjs /tmp/douyin_collected.json
    node collect_folders.mjs           # 产出 /tmp/douyin_union.json

    # 增量下载（已下载的自动跳过）
    bash run_all.sh

    # 索引与统计
    node make_index.mjs ~/Downloads/douyin_favorites
    node finalize.mjs  ~/Downloads/douyin_favorites

### 2.3 查看结果

    open ~/Downloads/douyin_favorites/index.html        # 画廊，点图看原图
    head -3 ~/Downloads/douyin_favorites/manifest.csv    # 台账
    cat ~/Downloads/douyin_favorites/summary.json        # 统计

## 3. 数据契约（改脚本前先看这里）

manifest.csv 每行一张图：

| 列 | 含义 |
| --- | --- |
| noteId | 笔记 ID（去重主键之一） |
| idx | 在本次清单中的序号（仅用于命名） |
| imgIndex | 该笔记内的图片序号（去重主键之二） |
| title / author | 笔记标题、作者昵称 |
| counter | 页面角标，如 1/9（用于张数校验） |
| file | 落盘文件名 |
| bytes | 字节数 |
| url | 原始签名 URL（可回溯） |

summary.json 字段：collectedNotes / downloadedNotes / coveragePct / completeNotes / partialNotes / images / megabytes。

## 4. 常见操作

| 想做的事 | 做法 |
| --- | --- |
| 只补某几条 | 手写 JSON {"notes":["https://www.douyin.com/note/<id>"]} 后 node download.mjs --list x.json --force |
| 提高成功率 | 减少并发（单窗口最稳），或重启 Chrome 以清理网络服务 |
| 转成 JPG | magick mogrify -format jpg ~/Downloads/douyin_favorites/images/*.webp |
| 清理冗余 | 确认后删除 ~/Downloads/douyin_favorites/_superseded/（本次 402 MB） |
| 换账号 | 换一个 --user-data-dir，重新扫码 |

## 5. 扩展一个新平台

1. 用 cdp.mjs 打开目标站点，先探 DOM（不要预设选择器）：列表项、详情页图集或视频源、翻页或滚动策略。
2. 写 collect_平台.mjs（产出统一结构 {notes:[url, ...]}），下载复用 download.mjs 的骨架，只改提取表达式与请求头。
3. 台账格式保持不变（manifest.csv 列名不动），make_index.mjs / finalize.mjs 即可直接复用。
4. 先跑 20 条验证路径稳定，再放量；失败清单与补漏轮同样复用。

## 6. 本仓库实际遵守的工程约定

- 原片只读：所有产物写新目录，验收脚本比对哈希。
- 闸门前置：每个阶段都有可运行的校验（selftest 或验收脚本），不达标不放量。
- 失败显式：失败写 failed.txt 与补漏清单，不静默丢弃。
- 可续跑：长任务一律支持断点，杀进程不丢进度。
- 参数留旋钮：阈值（ΔE <= 3、肤色 <= 5 度、P99_WARN=245 等）集中可改，改完写进报告。

## 界面布局（左右两栏）

App 界面分左右两栏，符合「左边设置、中间看结果」的使用习惯：

**左栏（设置与操作，可折叠）**

| 分组 | 内容 |
| --- | --- |
| 账号 | 新建 / 刷新账号，拉起并登录、探测登录态、打开收藏页、删除 |
| 平台选择 | 抖音 / B站 / 小红书 的接入难度与说明 |
| 平台操作 | B站 采集清单、导出 cookies、按清晰度下载、入库侧车元数据；抖音历史作者补采 |
| 清单 | 清单文件路径、载入、搜索、下载状态筛选、目录/命名模板与命名预览 |
| 任务 | 使用账号、端口、并发上限、输出目录；采集/下载/补漏/索引/转换等入口；任务列表（取消、重跑、看日志） |
| 元数据库 | 同步与统计（作品数、明细数、体积、作者数、收藏夹） |
| 日志 | 实时输出（也可从任务卡片点「日志」回看某条任务） |

**中栏（结果与进度）**

- 运行进度：运行中/排队中的任务卡片，带进度条与最近一行输出。进度从日志里的 `[12/345]` 或 `25/25 张` 解析，拿不到具体进度时显示不确定进度条；任务卡片上可直接取消或看日志。
- 提取结果：载入清单后按分类展示，分类维度可切换——**作者 / 收藏夹**（默认）、**下载状态**、**平台**。每个分类显示条数、已下载/待下载数量；卡片带封面、标题、点赞数与作品 ID，视频类会标注；点分组标题可折叠。

结果区还支持：搜索（标题或 ID）、按下载状态筛选、全选当前、清空勾选、下载选中、预览命名（把将要写入的路径打印到日志）。为保持流畅，单屏最多渲染 400 张卡片，超出会提示用搜索或筛选收窄。

## 使用流程（v0.3.1 起）

    选平台 → 配好该平台的选项 → 点「开始执行」→ 看底部运行进度

1. **选平台**：左侧「平台」下点 抖音 / B站 / 小红书。没选之前，右侧是空状态：标题写「未选择平台」、动作面板收起、「开始执行」按钮禁用。
2. **配置**（全部属于当前平台，各平台各记一套，关掉 App 也会保存）：
   - 账号：该平台自己的账号，可新建 / 拉起登录 / 探测 / 打开收藏页 / 删除
   - 下载内容：照片 / 视频 / 文字 + 图片 / 视频 / 文字三种格式
   - 清单：清单文件路径（默认在输出目录内的 preview.json）+ 载入
   - 任务：输出目录（可自定义文件夹）、转换目标与质量、任务列表
3. **点「开始执行」**：按勾选的步骤顺序跑一整轮。
   - 抖音：采集清单 → 下载 → 入库（台账 + 导出作者元数据）→（可选）转格式
   - B站：采集清单 → 下载（yt-dlp + cookies）→ 入库（台账 + 侧车元数据 + 作者元数据）→（可选）转格式
   - 账号登录（三个平台通用，在「账号」分页）：扫码登录（二维码直接显示在 App 里，扫完自动检测）/ 手机号验证码 / 账号密码；
     后两种会把浏览器窗口切到前台，由你在平台自己的页面里输入——App 不代填、不保存任何凭据。
   - 小红书：采集清单 → 下载（页面抓取，不做签名逆向）→ 入库 →（可选）转格式
     - 采集哪一页由「操作」分页的**采集页面**决定：留空采「发现」页（别人的笔记）；填自己的收藏页
       （`/user/profile/<你的 id>?tab=fav`，在浏览器里打开「我 → 收藏」后复制地址栏）就只采自己的收藏。
     - 收藏页里的笔记链接必须带 `xsec_token` 才打得开，所以请用本工具采到的清单去下载，别手工拼链接。
   - 底层由 tools/pipeline.mjs 编排，一个任务 = 一整轮；任一步失败即停下并说明停在哪一步，已完成的步骤保留。
4. **看进度**：底部「运行进度」固定显示，横向列出正在跑的任务（谁、第几张、第几条、百分比），可暂停 / 继续 / 取消 / 看日志。

### 平台工作区（六个分页）

选中平台后，右侧就是该平台的工作区，分页如下——每一页只放它自己的东西，避免「同一件事有好几个入口」：

| 分页 | 放什么 |
| --- | --- |
| 执行 | 步骤勾选（采集 / 下载 / 入库 / 转格式）、**开始执行**按钮、**① 检查新增**（比对清单与台账：已下载 X / 新增 Y，并列出新增条目；可「只下载新增」或「下载整个清单」）、输出目录；页面下方用一行文字说明「本轮会按什么顺序跑」 |
| 账号 | 该平台的账号（新建 / 拉起登录 / 扫码登录 / 手机号验证码 / 账号密码 / 探测 / 打开收藏页 / 删除）、当前账号、调试端口 |

| 清单 | 清单文件路径与「载入清单」 |
| 操作 | 该平台**特有的补充动作**（抖音：采集收藏夹 / 生成索引页 / 生成补漏清单；B站：导出 cookies） |
| 高级 | 队列并发与清理、维护动作（补采历史作者 / 重试失败项）、单独跑一次的格式转换、**检查更新 / 下载并安装**（可填自建更新清单地址）、任务列表 |

### 去掉的重复项（这次合并的重点）

| 之前有重复的 | 现在 |
| --- | --- |

### 已实现的十项优化（v0.3.0）

| # | 优化 | 实现与验证 |
| --- | --- | --- |
| 1 | 平台卡片显示关键状态 | 每个平台项下面显示「账号 N · 清单 N · 待下载 N · 失败 N」；实测抖音=账号1 · 清单2019 · 待下载972 · 失败1092 |

| 3 | 快速预设 | 「只采集 / 采集+下载 / 全流程」三个按钮一键切换步骤勾选；实测「只采集」只勾采集 |
| 4 | 选项互斥提醒 | 勾了转格式但图片格式是「保持原格式」时给出说明；没勾视频却选 mp3 也会提示 |
| 5 | 结果查看 → 下一轮范围 | 「设为下一轮下载」把勾选的 N 条写成 _next_run.json，执行页显示当前范围；pipeline 支持 --selected 只下这批 |
| 6 | 维护动作二次确认 | 补采作者 / 重试失败项改为「点一次变确认，再点一次才执行」（3 秒内有效） |
| 7 | 底部常驻失败入口 | 进度条右侧的「失败 N 条」按钮，点击跳到高级页并直接重跑失败项；0 条时置灰 |
| 8 | 启动健康检查 | 目录不存在 / 清单未采集 / 有失败 → 平台项标红并提示 |
| 9 | 元数据库跨平台总览 | 「元数据库」页顶部一行表格：两个平台各自的作品 / 已下载 / 待下载 / 作者数 |
| 10 | 快捷键 | ⌘⏎（或 Ctrl+Enter）开始执行；Esc 取消当前运行中的任务 |

### 后续可以继续做的优化建议

 1. 平台卡片上直接显示该平台的关键状态（已登录账号数、清单条数、已下载 / 待下载），一眼看出该做什么。
 2. 执行页显示「上次执行摘要」：成功/失败条数、耗时、最常见失败原因，点一下就能重试。
 3. 常用组合做成预设按钮：只采集 / 采集+下载 / 全流程，一次切换步骤勾选。
 4. 选项互斥提醒：勾了「转格式」但图片格式是「保持原格式」时给出提示，避免以为会转。
 5. 结果查看里加「把这一批加入下一轮执行」，把「挑选」和「执行」连起来。
 6. 维护动作（补采作者、重试失败项）加二次确认，注明影响范围。
 7. 底部进度条旁常驻一个「失败 N 条」入口，点击直达重试。
