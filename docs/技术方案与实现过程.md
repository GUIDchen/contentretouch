# 技术方案与实现过程：从抖音收藏批量下载图文

> 记录本项目的真实技术路径、关键决策、验证方式与踩坑修复。所有数字与结论均来自实测。

## 1. 需求与约束

| 项 | 内容 |
| --- | --- |
| 目标 | 读取当前电脑已登录抖音账号的收藏，把其中所有涉及图片的收藏（图文笔记）全部下载到本地一个文件夹 |
| 明确排除 | 视频收藏跳过；不下载音乐 / 合集 / 短剧 |
| 规模 | 1272 条图文笔记、12269 张图、约 4.2 GB |
| 环境 | macOS、Chrome 153、抖音桌面客户端 8.5.1（已登录）、Python 3.14 / Node 24 / ImageMagick |
| 合规约束 | 只读用户自己的收藏、不下 DRM 内容、不绕过风控（遇验证码即停手交还用户） |

## 2. 环境勘察：登录态到底在哪

动手前先确认「已登录」存在于哪一层，这个结论直接决定技术路线。

| 对象 | 实测 | 结论 |
| --- | --- | --- |
| 抖音桌面客户端 com.bytedance.douyin.desktop 8.5.1 | Cookie 库 68 条，.douyin.com 52 条，含 sessionid / sessionid_ss / passport_csrf_token | 有登录，但值为 Chromium v10（AES-GCM）加密，密钥在 macOS 钥匙串，不复用 |
| 桌面客户端调试端口 | 无任何监听端口（9222/9223/8888 均无响应） | 无法从外部挂载其页面 |
| Google Chrome（用户默认配置） | 12 条 douyin cookie，全是设备指纹类（ttwid / odin_tt / fpk1） | 未登录 |
| Edge / Safari | Edge 无 douyin cookie；Safari cookie 库 4 KB 且长期未更新 | 未登录 |

决策：不提取用户凭据（即便机器是用户本人的），改用「专用浏览器配置 + 扫码登录」，登录态只存在项目自己的 profile 里，与用户日常浏览器完全隔离。

- 专用配置：~/.dsh/douyin-profile
- 调试端口：127.0.0.1:9222

## 3. 技术选型：为什么是 CDP，而不是别的

| 方案 | 可行性 | 采用 |
| --- | --- | --- |
| 直接调 Web API（aweme/favorite 等） | 需要 a_bogus / X-Bogus 签名，算法随版本变动，维护成本极高 | 否 |
| 桌面客户端抓包 / 注入 | 客户端无调试端口，无法挂载 | 否 |
| Selenium / 无头浏览器 | 无头环境对反爬更敏感，且登录扫码不友好 | 否 |
| CDP 驱动真实 Chrome + 持久化 profile | 复用真实登录态与真实渲染路径，无需破解签名 | 是 |

核心工具是自写的零依赖 CDP 客户端 tools/douyin/cdp.mjs：Node 24 自带 WebSocket 与 fetch，直接走 /json/version → 浏览器级 WebSocket → Target.createTarget / attachToTarget → Runtime.evaluate，不引入 Puppeteer / Playwright。

## 4. 系统架构

    collect.mjs            滚动默认收藏列表 -> 收集 /note/ 链接
    collect_folders.mjs    遍历 13 个收藏夹 -> 逐个滚动收集 -> 与默认列表求并集
    download.mjs           逐条打开笔记页 -> 提取图集 -> 下载原图（多进程分片、断点续跑）
    make_retry.mjs         统计失败与「张数不足」的笔记 -> 生成补漏清单
    make_index.mjs         manifest.csv -> index.html 画廊 + summary.json
    finalize.mjs           覆盖率统计 + 重复文件归档到 _superseded/
    run_all.sh             一键：首轮并行 -> 失败重试 -> 生成索引

数据流：

    收藏页(DOM) --href--> note 链接集合(JSON)
                          |
                          v
                 笔记页 DOM img[src 含 biz_tag=aweme_images]
                          |
                          v
                逐张 fetch(带 Referer / UA) --> images/序号_笔记ID_图片序号.webp
                          |
                          v
                manifest.csv（逐张台账）--聚合--> index.html + summary.json

## 5. 关键实现细节

### 5.1 列表采集
- 同时滚动 window 与所有可滚动容器到底部，直到链接数不再增长（最多 40 轮，每轮间隔 1.3-1.6 秒）。
- 去重依据是 a[href 含 /note/] 的 href；默认列表得 1031 条。
- 收藏夹是 DIV 卡片（无 href），按文本匹配卡片后 click() 进入，逐个滚动收集，得 241 条夹内笔记。两部分互不包含，必须都抓。

### 5.2 图集提取
- 首选 img[src 含 biz_tag=aweme_images]，按对象键去重。
- 兜底：该标记不存在时，取 naturalWidth >= 800 且非头像（排除 aweme-avatar、/100x100/）的图片。
- 计数校验：页面角标「4/6」给出声明张数，提取数不足则继续轮询（笔记轮播会自动前进，逐轮累积）。

### 5.3 图片下载
- 必须使用页面里带签名的完整 URL（去掉 ~tplv- 变换参数会 403）。
- Node fetch + Referer: https://www.douyin.com/ + 桌面 UA；3 次重试 + 退避。
- 保存为 序号_笔记ID_图片序号.扩展名（webp / jpg / png 按 Content-Type 决定）。

### 5.4 并发与窗口可见性
CDP 新建的标签页默认是后台标签，后台标签不触发图片懒加载，导致提取为空。
修复：每个 worker 用 Target.createTarget({newWindow:true}) 建独立窗口，并在每次导航后 Page.bringToFront；同时对 Chrome 追加 --disable-backgrounding-occluded-windows、--disable-renderer-backgrounding、--disable-background-timer-throttling。

### 5.5 断点续跑
- 启动时读 manifest.csv 的 noteId 集合，已完成的直接跳过（秒级掠过）。
- 失败写入 failed.txt（URL + 原因）；make_retry.mjs 合并「失败」与「张数不足」生成补漏清单，--force 强制重刷。

### 5.6 去重与收尾
同一条笔记可能被下载多次（部分成功 -> 补漏）。索引按 (笔记ID, 图片序号) 去重，保留最后一次拿到的文件；被取代的副本移入 _superseded/（本次 1041 个 / 402 MB），既不丢数据，也不让画廊出现重复图。

## 6. 验证方式与实测证据

| 验证项 | 方法 | 结果 |
| --- | --- | --- |
| 覆盖率 | 并集清单 vs manifest 去重 | 1272 / 1272 = 100%，缺 0 |
| 张数完整度 | 每笔记文件数 vs 页面声明张数 | 1270 完整 / 2 条不足（页面计数歧义） |
| 文件真实性 | file 命令抽样 | 有效 webp / jpg / png，多为 2160x3840 |
| 索引一致性 | images 目录文件数 vs index.html 引用数 | 12269 vs 24539（每张被 a 与 img 各引用一次，一致） |
| 画廊结构 | 统计 class="note" 卡片数 | 1272 张卡片 |

## 7. 四个坑：现象、根因、修复

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 大批「未取到图片」，成功率 50-70% | CDP 后台标签不加载懒加载图 | 独立窗口 + bringToFront + 关闭渲染节流；单窗口测试 11/11 全成 |
| 2 | 补漏轮整轮失败（0 成功） | 重试清单存完整 URL，脚本又拼了一次 https:，变成 https://https//... | URL 归一化改为幂等函数 |
| 3 | 页面变 chrome-error / DNS_PROBE_FINISHED_NXDOMAIN，而 curl 正常 | Chrome 网络服务异常，不是系统网络问题 | 重启该 Chrome 实例；随后同一批 130 条一次过 |
| 4 | CDP 调用开始超时 | 反复中断积累了大量调试标签页 | 清理到 1 个标签页，脚本改为每次自建自关 |

## 8. 局限与后续

- 图片是笔记页展示分辨率的 webp（由签名 URL 决定），不是平台内部原图；需要 JPG 可整体转换。
- 页面结构改版会让选择器失效，脚本有兜底但不保证永久可用。
- 站点侧对高频访问有节流，规模越大越需要控制并发（建议 2-4 个窗口）。
- 不绕过验证码：出现即停手交还人工。
