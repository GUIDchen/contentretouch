# M2：命令行闭环（参考组 → 参数 → 出图 → 度量 → 收敛 → 导出）

> 复查结论把 M2/M3 换了位：先证明「参数 + 批量出图」这条管线在自己片子上跑得通，再套 UI。
> 这一篇就是 M2 的交付：一个命令行工具，已经用你的 8 张婚片真跑过。

## 1. 工具

    tools/retouch/retouch.swift   →  编译成 tools/retouch/retouch

用法：

    ./tools/retouch/retouch --style style_out/style_report.json --cluster 2 \
        --in <原片目录> --out <输出目录> [--limit N] [--iterations 3] \
        [--format jpeg|tiff] [--quality 95] [--report out.json] [--dry-run]

## 2. 闭环是怎么算的（关键设计）

**目标向量用「形状量」，不是绝对亮度**：

    q5 / q50 / q95 = 把每张片自己的 p1..p99 归一化到 0..1 之后的分位位置
    sat            = 平均饱和度
    warmSh / warmHi = 阴影与高光的暖冷（R-B）

为什么不用绝对亮度：参考组的 p50 低，往往是因为「那批片子本身就拍得暗」，把客片按绝对亮度拉过去等于改了曝光，不是改风格。
形状量描述的是**调色手法**，所以才是该对齐的东西。

每张片的流程：

    ① 量原片 → ② 由风格块 + 本图自适应（按亮度/高光贴顶收敛曝光与 gamma）生成初始参数
    → ③ Core Image 出图 → ④ 重新量成片 → ⑤ 与目标向量比误差 → ⑥ 按比例微调（gamma / 抬黑 / 降饱和 / 分色调）
    → 循环最多 3 轮，**取误差最小的那一版**（不是取最后一版）

## 3. 两道保护（都是实测踩出来的）

1. **原片已接近该风格时不套用**：
   实测风格 3（暗调·暖）对 wedding_01 是「误差 0.272 → 0.313」——越修越远，因为那张片子本来就很接近这个风格。
   现在遇到这种情况直接**原样复制**并在报告里标 `alreadyClose`，界面上会提示「原片已接近该风格，未套用」。
2. **与本风格差异过大时给警告**：残差 > 1.0 记 `farFromStyle`，提示「建议换参考组」——
   避免用户拿到一个「参数已经顶到上限、但根本不像」的结果还以为是成功。

## 4. 实测结果（你的 8 张婚片，风格 2：亮调·抬黑·低饱和）

| 指标 | 数值 |
| --- | --- |
| 张数 | 8 / 8 成功，0 失败 |
| 耗时 | **1.0 秒**（7.6 张/秒；纯试算 28 张/秒） |
| 风格向量误差 | 平均 **1.150 → 0.706**（每张都下降） |
| 逐张参数 | gamma 0.80~1.35、抬黑 17~32、降饱和 25~47（**逐张不同**，这就是自适应） |
| 输出 | JPEG 质量 95，约 0.8~0.9 MB/张 |
| 视觉 | 见 docs/shots/M2_婚片前后对比.jpg（上排原片 / 下排成片）：暗部抬起来、黑西装变暖灰、红色转陶土色、整体变亮变柔 |

## 5. 诚实的不足

- **gamma 有 3/8 撞到 1.35 上限**：说明目标风格比这批片子亮得多，再往上顶会失真，所以宁可停在上限；
- **残差没有收敛到 0**（0.36~1.32）：6 个旋钮无法完全复制一个风格的统计特征，这是方法本身的边界，不是 bug；
- 明确是**全局影调与色彩**的匹配：不做磨皮、不做局部压暗、不做液化（那是 M5 的范围，且达不到像素蛋糕的水平）；
- 色彩管理目前固定 sRGB 工作空间 + sRGB 输出，**还没做像素级校验**（复查清单里第 4 条，M3 补）；
- 大图性能未压测：这批原片是 1080×1620，真正 6000×4000 的原图要再测一轮。
