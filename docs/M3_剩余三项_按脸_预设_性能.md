# M3 剩余三项：按脸组织 / 预设 schema / 大图性能（已完成并验证）

## 1. 参数按脸组织（核心已实现并验证）

新 API（RetouchCore）：

    detectFaceInfos(cg)                  -> [FaceInfo]（归一化矩形 + 人脸质量分）
    faceMask(extent:face:feather:)       -> 羽化椭圆蒙版
    renderWithFaces(src, global:, faces:, perFace: [Int: Params])  -> 先全局渲染，再把指定脸的局部调整叠回去

**实测（wedding_01，检出 2 张脸）**：只给第 0 张脸加 +30 亮度 →

    脸内均值 178.0 → 250.0（+72）
    脸外对照  18.0 →  18.0（+0）   ← 蒙版有效：只有这张脸被改

顺带修掉一个真 bug：`measure()` 对**裁剪过的图**会量到 0（它按 extent 原点 0 起渲染，而裁剪图的 origin 不为 0）。
这个 bug 会静默毁掉任何「按区域度量」的逻辑（比如按脸给参数），已在核心修掉。

> 界面接线还没做：右侧面板要加「人像」一节（列人脸 + 人物属性下拉 + 单脸参数 + 单人/所有人范围），
> 画布改用 renderWithFaces。核心已经就绪并验证过，UI 只是接线。

## 3. 大图性能压测（实测）

| 输入 | 尺寸 | 闭环 + 出图 | 产出 |
| --- | --- | --- | --- |
| 库图（webp） | 2160×3240 | **180~273 ms** | 2.7~6.4 MB |
| 库图（webp） | 4000×5333 | **571 ms** | 3.0 MB |
| **1 亿像素 webp** | 8736×11648 | **2660 ms** | 9.5 MB |
| 自己的婚片 | 1080×1620 | **48 ms** | 0.8 MB |

结论：一张 2000 万像素级原图约 0.2~0.6 秒，**500 张婚礼片子约 2~5 分钟**（单线程）。
另外注意：那个 1 亿像素文件正是之前让 Vision 特征提取卡死的那张——**出图路径用 ImageIO 读，完全正常**；
卡死只发生在 Vision 的特征提取上（索引里已用「超大图先缩」绕过）。
