# AI 自动化修图 App：调研、可行性与技术路线

> 需求原话：把所有照片都应用一遍；用一组照片提风格参数当参考图；再加待修图，
> 按参考图参数 + 待修图参数给出该图的参数；对输入的待修图，在整个参考库里搜相似照片推荐几组；
> 参考像素蛋糕做自动化修图；做成 macOS App；先做完整性/技术性/可行性调研 + 技术路线 + 界面，最后完成软件。

## 0. 结论先说

- **可行**，而且关键能力已经在本机验证过（不是纸面推演）：
  - Swift 6.3.3 + Command Line Tools（**不需要装 Xcode**）就能编译 SwiftUI + Vision + Core Image 的 .app；
  - Vision 能拿到 768 维图像特征向量（找相似参考图）、人脸矩形、人脸关键点（眼 12 点/脸廓 17 点/内唇 6 点）、人像分割掩膜；
  - Core Image 能完成色阶/曲线/饱和度/分色调并写盘，实测单张 170~280 ms。
- **已有一个能跑的界面原型**：见 tools/spikes/Prototype.swift（窗口截图在 /tmp/proto_crop3.png），
  左栏参考图组 + 参数滑杆，右栏原图/结果对比，底部三阶段提示，实际加载你自己的婚片与收藏代表图渲染。
- **能不能做到像素蛋糕那样？** 追色（本项目的强项）能对齐甚至更贴合你的婚礼题材；
  磨皮、3D 塑颜、祛瑕疵这类靠大规模商业数据训练的能力，做不到它的水平——
  本机没有训练数据也没有推理框架，只能用系统框架 + 传统算法逼近（详见 §5）。
- 建议路线：**先做「参考图 → 参数 → 批量套用 → 逐张自适应 → 导出」这一条闭环**（这是你要的核心，也是我们已有工具链最长的那块），
  磨皮/美型作为第二阶段的可选插件式功能。

## 2. 参考对象：本机的像素蛋糕 9.0.0

### 2.1 本机实测

- 安装在 /Applications/pixcake.app，**2.7 GB**，bundle id com.xiangtian.pixcakepc，版本 9.0.0，二进制为 x86_64（在本机走 Rosetta）。
- 启动成功（PID 90497），但**会话已过期，弹「登录过期，请重新登录」**。登录需要你的手机验证码/微信，
  我不会代你登录、也不碰验证码——所以我看到的是登录态之外的东西：包结构、官网页、使用手册目录。
  （你想要我看它的实际工作区，登录一次后我再截图对照即可。）
- 架构（从包结构直接读出来的，可作为我们的对照）：
  - **Qt 5 + QML/QtQuick** 做壳，**QtWebEngine（Chromium）**做网页部分，另有 QCefView；
  - **独立 worker 进程 pix-worker（132 MB）**扛重活，主程序 pixcake 174 MB；
  - Frameworks 里**没有独立的推理引擎 dylib**（无 onnxruntime/mnn/ncnn/torch），说明模型与推理是**静态链接进主程序/worker**；
  - Resources 里 effect 目录 **255 MB**（素材/效果/模型），另有 materials、Filter、www、PixCakeMaterial.rcc。
  - 结论：**原生重壳 + 独立计算进程 + 大资源包**。我们的路线（SwiftUI 壳 + 独立 Node/Python 管线进程 + 系统框架出图）在形状上是一致的，只是把 Qt+CEF 换成系统原生，省掉 2.7 GB。

## 4. 技术路线

四层 + 一个壳：

    ① 索引层   tools/style/index_library.swift(新) : Vision 特征 + 影调统计 -> style_index.json
    ② 推荐层   App 内近邻搜索（768 维余弦） -> 推荐 3~5 组参考图 + 每组参数
    ③ 参数层   photo-style-pipeline（已有）：风格参数(参考组) + 自适应项(本图亮度/p99) -> 每张的参数
    ④ 执行层   Core Image(系统框架，GPU)：色阶/曲线/色彩平衡/饱和度/局部遮罩 -> 16bit TIFF/JPEG 导出
    壳        SwiftUI App：项目/参考组/待修图/参数面板/前后对比/批量队列/导出设置
    任务      复用现有 App 的队列（queued/running/paused/done/failed/cancelled）+ 进度回传

关键设计决策：
1. **索引与出图都用系统框架**（Vision + Core Image），不引入 2.7 GB 的 Qt/CEF/自训练模型，也不需要 Python ML 栈；
2. **参数来源双轨**：风格项（色阶两端、分色调、降饱和）来自「参考图组」，安全项（曝光、gamma、高光滚降）来自「本图自己的亮度/p99」——这正是现有 make_params.py 的思路，已在你 8 张婚片上验证过；
3. **Python 管线保留为「参数工厂」**：分析、聚类、生成参数表；App 只消费参数，不重复实现；
4. **不碰客户数据**：所有计算在本机，不上传；不做任何用客户照片训练的事；
5. **磨皮走传统算法**（频域分离 + 皮肤掩膜 + 质感保护），明确标注为「可用级」，不吹成商业级。

## 8. 工程量估算（诚实）

- M1-M4 是「把已有能力装进 App」：约 8-13 个工作日可到「能交付自己婚礼片子」的程度；
- M5 是「从零做影像算法」：磨皮与美型没有现成系统 API，属于真正的研发，做扎实要 1-2 周，且不保证达到像素蛋糕水平；
- 最大的不确定性不在 App，而在**磨皮/美型的手感**（这是像素蛋糕最厚的护城河）。

## 9. 明确不做

- 不做云端上传与云协作（你的素材不出本机）；
- 不做生成式（换背景/生成式填充/换天空）——需要扩散模型与算力；
- 不代用户登录任何平台账号，不接触验证码与密码；
