## 二、逻辑错误与隐患（按严重度）

### 高

1. **断点续跑的粒度错了（数据完整性）** `tools/douyin/download.mjs:34`
   manifest 里只要有该 noteId 的任意一行，整条笔记就被跳过。实测：13489 行 / 1293 个 id，其中 2 条笔记只落了 3/10 与 2/10 张，且都在 failed.txt 里——而 failed.txt 的 850 个 id **全部**已在 manifest 中，意味着补漏轮会把它们全部 skip，永远补不齐。
   建议：done 改为「id → 已落盘张数」，张数达标才跳过；应急可给补漏轮加 `--force`。

2. **文件名未清洗逗号，会让 manifest 断列（数据完整性）** `tools/lib/naming.mjs:5`
   实测：B站 313 条清单里有 1 条标题含逗号（`达芬奇version 19的新功能 (Music Remix, Dialogue Seperator, EQ实时波形,…)`），按默认命名模板 `{title}_{id}` 生成的文件名会让那一行 CSV 变成 12 列，而所有读取方都按 `split(",")` 定位列 → file/bytes/url 全错位。**已修**（见文末）。

3. **暂停中的任务会被「清空已结束」连根拔掉，并发位永久泄漏** `jobs.rs:415`
   `clear_finished` 的 retain 只保留 running/queued，paused 被删但子进程仍在（SIGSTOP 只是挂起）→ 并发位永不释放。连续两次「暂停 + 清理」就能把 max=2 的槽位占满，之后所有任务永远停在排队。**已修**。

4. **任务在没有脚本根目录时会把队列堵死** `jobs.rs:165`
   `root` 为 None 时只 `finish(failed)` 就 return，既不减并发计数也不 pump。触发条件真实存在：打包缺失 tools/ 或在仓库外运行。**已修**。

5. **同步命令跑在主线程，界面会冻结** `lib.rs:332/344/281/134`
   `launch_profile` 最长等 16 秒（30×500ms 轮询），`probe_profile`/`list_profiles` 会起 curl，`library_stats` 会等 node 子进程。Tauri 只有 `async` 命令才另起线程。**已修**（给这四个命令加了 `#[tauri::command(async)]`）。

6. **取消的状态机有两个洞** `jobs.rs:304`
   ① 取消「刚出队、还没 spawn」的任务会静默失败（child 还是 None，却返回「已终止」，随后 start 又把状态写回 running）；② 对已结束的任务调用 cancel 会把记录改成 cancelled。**已修**（状态白名单 + 出队后置状态 + spawn 后二次确认）。

7. **暂停/取消只作用于直接子进程** `jobs.rs:326/348`
   真正的长活儿在孙子进程里（yt-dlp、magick、ffmpeg），取消后它们继续写盘，暂停也没停住。**已修**（子进程独立进程组 + 对 `-pid` 发信号）。

8. **e2e_drill.sh 默认输出目录跳出仓库一级** `tools/e2e_drill.sh:6`
   实测求值为 `.../DeepSeek-Harness-Projects/douyin_favorites`（`dirname "$0"/../..` 多退了一级）——是我上一轮改默认路径时引入的。**已修**。

### 中

9. **界面「调试端口」只写不读** `app/html/app.js`：所有任务默认打 9222，多账号场景会静默操作错账号。**已修**（脚本侧支持 `--port`，界面按所选账号端口下发；连不上时给出人话提示）。
10. **未勾选任何条目时「下载选中」= 下载全部** `preview.rs:68`（空集合被当作全选）。**已修**（前端守卫）。
11. **未选平台时输出目录为空**：`_selected.json` 会写进进程 cwd、打开目录会指向 `/images`。**已修**（前端守卫）。
12. **清单路径三处不一致**：默认读 `/tmp/douyin_collected_v2.json`，采集写 `/tmp/douyin_collected.json`，增量下载写 `/tmp/douyin_union.json`，而 `_v2` 全仓无人产出。**已修**（清单改为产出目录内的 `preview.json`，采集与载入共用同一路径）。
13. **界面按钮「入库B站侧车元数据」是假成功**：脚本没有 `--ingest-info` 分支，落到 else 打印「没有指定动作」后以 0 退出，界面显示绿色「已完成」。**已修**（功能补齐，见文末）。
14. **项目里有两份同名源码，真实项目落后**：`dsh-xiuti/tools/douyin/library.mjs`（344 行，含 `--ingest-info`/`--platform`/迁移）比真实项目的（327 行）新；`tools/bilibili/open_login.mjs` 只存在于旧目录。**已修**（合并补齐）。
15. **账号 id 用 `p{len+1}`**：删掉中间账号后必然撞 id，两个账号会共用同一 user-data-dir（串号）。**已修**（改用最大编号 +1）。
16. **`profiles.json` 损坏即静默重新播种**：用户账号配置直接丢失；`save` 也是非原子写。**未修**（建议：解析失败先备份再播种，写入改临时文件 + rename）。
17. **取消只 kill 直接子进程 → 同 7**（已随进程组一并解决）。
18. **子进程 stderr 被丢弃**：node 失败时界面只能看到空白的「原始输出」。**已修**（library_stats 现在带 stderr 与退出码）。
19. **`set_max_concurrent` 只改值不调度**：调大上限后排队的任务不会立刻启动。**已修**（补 `pump()`）。
20. **`start_job` 不校验脚本路径**：前端可投递根目录之外的任意可执行文件。**已修**（校验前缀 + 存在性）。
21. **CDP 调用无超时**：`collect.mjs`、`collect_folders.mjs`、B站 `collect/cookies`、`cdp.mjs` 在网络卡死时会永久挂起（只有 download/backfill 修过）。**未修**。
22. **`download.mjs:50` 的 `wsDead` 只写不读**：浏览器掉线后每条笔记白等 30 秒超时跑完整份清单。**未修**。
23. **magick / yt-dlp 缺失时静默降级**：转格式失败不报错、视频缺失与「本来没视频」不可区分。**未修**。
24. **`make_retry.mjs` 对 counter 为空的笔记永远判不清**：102 行（97 个 id）counter 为空 → declared=0 → 既不进补漏清单又算「完整」。**未修**。
25. **`finalize.mjs` 只看 images/ 一层**：用 `--dir-template` 产出子目录后，整棵子目录会被当成「被取代」搬进 `_superseded/`。**未修**（当前尚无子目录，属潜伏）。
26. **`_superseded/` 与 manifest 失联**：1055 条 manifest 记录指向已不存在的文件（文件已移到 `_superseded/`，名字没变），导致这些条目的本地缩略图/打开目录会失败。**未修**（建议加一个 `--repoint-superseded` 或把文件并回去）。
27. **界面「打开收藏页」写死抖音 URL**：B站/小红书账号点了会跳到抖音。**未修**。

### 6.1 真实截图暴露的一个严重 bug（已修）

### 7.4 账号登录方式（本轮新增）

需求是「在账号里加扫码、手机号短信、账号密码三种登录」。做法与边界：

| 方式 | 做了什么 | 真机验证 |
| --- | --- | --- |
| 扫码登录 | 打开平台登录页 → 切到扫码 → **把二维码截回 App 显示**（clip + scale 2，输出 608×608 / 760×760）→ 轮询探测登录成功 | 三平台全通过；截图已人工确认是完整二维码 |
| 手机号验证码 | 打开登录页 → 点开「验证码 / 短信 / 手机号登录」标签 → 浏览器窗口切到前台，用户自己输入 | 抖音「验证码登录」、B站「短信登录」、小红书「手机号登录」均命中 |
| 账号密码 | 同上，切到「密码登录」标签 | 抖音、B站命中；小红书没有密码入口，如实提示而不是假装成功 |

**凭据边界（有意为之）**：App 只做「打开页面 / 切标签 / 截二维码 / 探测登录态」，**不代填、不保存、不记录**手机号与密码——这类信息始终由用户在平台自己的页面里输入。理由：App 一旦经手凭据，日志、内存、配置里就都有了副本；而自动提交登录表单还会触碰各平台的风控与用户协议，代价远大于省下的那点操作。

**验证方式**：用一个**全新的临时 Chrome profile**（未登录，端口 9455）跑通三种方式 × 三个平台——日常用的那三个账号本来就是登录状态，只有新 profile 才会真正出现登录框与二维码。测试用的浏览器与临时目录已删除。

期间修掉的真机问题（第一轮）：

1. 首页冷启动前几秒 DOM 是空的 → 判断「没有登录入口」为时过早；改为轮询等内容出现再判断。
2. 抖音首页默认不弹登录框 → 需要先点导航里的「登录」（新增精确匹配的入口点击，避免误点「扫码登录」）。
3. 二维码比弹窗晚几秒渲染（先显示加载态）→ 改为轮询等待（最多 30 秒）。
