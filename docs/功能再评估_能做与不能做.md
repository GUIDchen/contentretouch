> 每一行给两样东西：**判定**（能做 / 近似 / 不能做）与**能到多少**（打分标准见下）。
> 「不能做」的项目已经在界面上**占位**（右栏「待开发」面板，灰色 + 「以后开发」标签），代码里保留位置，不假装可用。

打分口径（0~5）：

    5 = 与像素蛋糕同级，可直接用于商业交付
    4 = 客户看不出明显差别
    3 = 可用，但需要在批量里抽查
    2 = 能看出效果，但需要人工兜底
    1 = 只能做演示，不适合交付
    0 = 本机做不了

**共同原因**：本机没有推理框架（无 PyTorch / ONNX Runtime / CoreML 模型文件），也没有训练数据；
这些功能的门槛是**模型**，不是工程量。要真做，得先解决「跑模型」这件事（例如 CoreML + 自训或第三方授权模型）。

## 三、本轮继续做的事

1. **祛黑白边（裁剪的第一步）**：已实现 `detectBorderCrop`（缩到 256px 逐行逐列判「连续纯黑/纯白」）。
   **实测：半成品**——纯色干净图正确不裁（100% 保留 ✓）；带 60px 白边的图只裁掉约 58px 宽、**高度方向完全没裁**；带 45px 黑边的图裁到 1089×1630（目标 1080×1620，接近但偏差 9px）。
   已经知道要修哪儿：比例换算与 y 轴方向（位图行序）没对齐。**不把它算作完成**。
2. **占位面板**：右栏新增「待开发」入口，列出上表 10 项不可做的功能，灰色 + 「以后开发」标签。

## 四、结论：整体能到像素蛋糕的几成

- **调色 / 追色 / 批量交付**：能到 **7~8 成**（这是我们最强的一块，而且比它多一层「从你自己的库里找参考组」）；
- **磨皮 / 瑕疵 / 塑形**：能到 **3~4 成**（可用级，不能商业对标）；
- **生成式（换装/换天/填充/拉龄…）**：**0 成**，本机做不了；
- 综合：**把「婚礼批量调色交付」这件事做到 7 成以上是现实的；把「像素蛋糕全功能」做到 5 成是不可能的**，差距集中在模型。
