# 变更记录

## v0.3.1

### 小红书真机联调：修掉 6 个真问题

前几轮小红书只验证到「未登录时的提示」——脚本里登录之后的那条分支从未真正执行过。这次在已登录的浏览器上把「采集 → 下载 → 入库」整条跑通，问题才暴露出来：

- **采到的链接打不开（致命）**：收藏页的卡片上同时挂着两条链接——隐藏的 `<a href="/explore/<id>">`（没有 `xsec_token`，打开是「你访问的页面不见了」）和封面上的 `/user/profile/<uid>/<id>?xsec_token=…`（站点自己用的那条）。采集器只取了前者，于是整份清单打开全是 404。现改为按卡片采集，并按 id 去重时**优先保留带 token 的链接**（自检里加了正反两个方向的回归断言）。
- **采集表达式语法错误**：页面 eval 的模板字符串里 `split('\n')` 被吃掉一层转义，注入到页面的其实是真换行，直接 `SyntaxError`。之前查不出来，是因为脚本总在「未登录」检查处就退出了，从来没走到这一步。
- **假成功（最危险）**：下载器把「页面不见了」那张 369 字节的搜索图标（`fe-static…/standardSearchIcon.svg`）当笔记图片存了下来，还打印「成功 3」。现在：① 认得出错误页并直接报「笔记打不开」；② 只取自然宽度 ≥ 400 的图；③ 排除 `fe-static` 与 `.svg`。
- **把「相关推荐」当成笔记图片**：图集限定到 `.media-container` / `#noteContainer .swiper-slide`，否则页面底部推荐位的封面也算进来（14 张的笔记曾下成 52 张）。
- **图集被截断**：轮播是异步渲染的，原来「一有图就收工」，冷启动时 8 张的笔记只下到 1 张。现改为「达到页面自报张数，或张数连续两轮不再增长」才收工，并新增张数不符提示（不静默少下）。
- **扩展名说谎**：小红书返回的是 webp，却被硬写成 `.jpg`。现按响应 content-type 定后缀。
- **进程不收尾**：跑完不退出（开着的调试连接吊住事件循环，而 Node 的 WebSocket 没有 `unref`），补上显式退出。

### CDP 样板合并（上一轮留下的维护性债务）

- 新增 `tools/lib/cdp.mjs`：一套「连接 / 超时 / 挑标签页 / 求值」实现。抖音（采集·收藏夹·作者补采·下载）、B站（采集·cookies·登录）、小红书（采集·下载）与 `session_probe` 共 10 个脚本全部改用它——原先每个文件各自内联 15~20 行一模一样的收发样板，改一次超时逻辑要改九个文件。合并后全仓 `new WebSocket` 只剩共享模块自己。
- 抖音失败清单里的 `https://https://…`（历史遗留的重复协议前缀）不再被原样回写：`norm()` 会剥掉重复前缀，回写也写规范化后的地址，并按 url 去重只保留最新一次的原因。

### 自动更新：密钥 + 签名 + 验签（这次真跑通了）

- **密钥已生成**：`~/.tauri/harvester.key`（私钥，600）、`~/.tauri/harvester.key.password`（口令，600）、`~/.tauri/harvester.key.pub`（公钥）。公钥已写进 `tauri.conf.json` 的 `plugins.updater.pubkey`——私钥与口令请抄进密码管理器，本机磁盘坏掉 = 更新通道断掉。
- **更新产物**：打开 `bundle.createUpdaterArtifacts` 后，构建会自动多出 `ContentHarvester.app.tar.gz` 与 `.sig`（用私钥自动签）。macOS 的 updater 吃的是 **tar.gz 而不是 dmg**，清单里的 url 与签名都必须对这份 tar.gz。
- **新增 `tools/dist/verify_signature.mjs`**：把「清单 → 更新包 → 签名 → 公钥」整条链路验一遍（自己解析 minisign 格式 + Ed25519 校验，零依赖）。自检覆盖预哈希/原文两种模式，以及「改一个字节必须失败」「换公钥必须失败」。
- **App 里能检查更新**：接入 tauri-plugin-updater，新增 `check_update` 命令与「高级 → 更新 → 检查更新」界面（只检查 + 验签，**不自动下载安装**）。
- **端到端实测**（本地 http + App 自己的代码路径 `--check-update`）：读到 0.3.2 清单 → 报告新版本 → 下载 3.0 MB 更新包并验签通过；**把更新包改一个字节 → signature verification failed**；版本相同 → 已是最新版本。
### 账号登录：扫码 / 手机号验证码 / 账号密码

- 账号分页新增三种登录方式，三个平台通用：
  - **扫码登录**：把登录页上的二维码**截回 App 里显示**（190px、清晰可扫），扫完自动轮询检测登录成功并刷新账号状态，不用再去浏览器窗口里找二维码。
  - **手机号验证码 / 账号密码**：自动切到该平台的对应标签（抖音「验证码登录 / 密码登录」、B站「短信登录 / 密码登录」、小红书「手机号登录」），并把浏览器窗口切到前台，由你在平台页面里输入。
- **凭据边界（有意为之）**：App 不代填、不保存、不记录手机号与密码——只做「打开页面 + 切标签 + 截二维码 + 探测登录态」。登录态落在该账号专属的浏览器目录里。
- 新增 `tools/login.mjs`（零依赖，复用 `tools/lib/cdp.mjs`），自带自检（二维码挑选 3 例 + 标签匹配 4 例）；三平台 × 三方式的真机验证见审查报告 §7.4。
- 顺手修掉三个真机才暴露的坑：首页冷启动前几秒是空白（先等内容出现再判断）、二维码比弹窗晚几秒渲染（改成轮询等待）、抖音首页要先点导航里的「登录」才会弹登录框。

### 账号登录模块的第二轮打磨（同一次需求的收尾）

第一版能用之后，真机又暴露了三个问题，都已修：

- **手机号 / 密码方式没有成功反馈**：原来只有扫码会轮询登录态，输完验证码后 App 不会告诉你成功了。现在三种方式都会轮询（每 3 秒一次，最多 5 分钟），登录成功即刷新账号状态并关闭二维码区。
- **二维码失效要手动刷**：新增 `--mode check`（只看当前页面，**不重新导航**——重新加载会把用户正在扫的那张码换掉）；界面每约 15 秒检查一次，失效就自动换一张。
- **冷启动取码会超时**：后台/被遮挡的窗口在 macOS 上可能不参与合成，`Page.captureScreenshot` 会一直不返回（实测 20 秒超时）。现在截图前先把该页置前（登录场景本来就该在前台），并在失败时退回 `fromSurface:false` 从渲染器取帧。冷启动整体约 40 秒，界面文案也改成「首次冷启动可能要等半分钟」。
- 顺带：如果该账号的浏览器还没启动，点登录会**先自动拉起**它（不再卡在「浏览器还没起来」）。

### 从参考图库反推修图风格（analysis → 参数）

- 新增 `photo-style-pipeline/style_from_library.py`：从图库（如抖音收藏的 13k 张）里**量化**出风格。
  - 每件作品取 1 张（按 manifest 去重）→ 量 17 项全局特征（分位影调、归一化曲线形状、分区暖冷/绿洋红、平均饱和度、高光贴顶率、细节能量）→ k-means 聚类。
  - 输出：`style_report.md`（风格表 + 命名 + 参数 + 四步用法）、`styles.jsx`（可直接替换 batch.jsx 的 `var S`）、`style_report.json`、`cluster_N.jpg`（每风格 12 张代表图拼图）。
- 新增 `photo-style-pipeline/apply_style_preview.py`：把参数**真的套**到一张自己的片子上出前后对比（左原图 / 右套风格），用来判断力度是否合适；像素级成片仍由 PS 的 batch.jsx 出。
- 两个脚本都带 `--selftest`（尺寸过滤 / 影调方向 / 饱和度方向 / 聚类可分 / 参数范围 / 恒等不变 / 抬黑 / 偏暖 / 降饱和）。
- 实测（抖音收藏，400 张样本，43 秒）：分出 6 种影调-色彩家族，最大两类是「亮调抬黑低饱和」114 张与「暗调冷暗暖高分色调」128 张。

- **方法论上纠了两个错**（都是自查发现的，值得记下来）：
  1. 一开始把参考片的**绝对** p99 当色阶白场用 —— 参考片偏暗是因为场景暗，不是手法；那样会把正常曝光的片子推爆。改成「形状归一化」（把每张片自己的 p1..p99 映射到 0..1 再统计），参数才代表调色手法。
  2. 色彩平衡的权重被当成级数直接加到通道上，结果整片染橙。改成「cb 用 PS 的 -100~100 刻度、每 100 对应 ±26 级」，并用真实婚片前后对比肉眼复核。
### 增量下载：先比对、再问你要不要下新增

需求是「下次同账号同操作时，先看哪些已经下过，别重复下；把新增的挑出来，让我决定下不下」。做法：

- 「执行」页新增 **① 检查新增**：用当前清单与该输出目录的台账（manifest）比对，给出
  `清单 N 条 ｜ 已下载 X 条 ｜ 新增 Y 条`，并列出新增条目的标题/作者（最多 30 条），
  同时标出「这份清单更新于什么时候」，避免拿一份很旧的清单做判断。
- 两个按钮由你选：
  - **只下载新增的 Y 条**：把新增条目写成 `_next_run.json`（下一轮范围）并立刻开跑；这轮会**自动取消「采集清单」步骤**——否则清单会在检查之后又变，下的还是旧范围。
  - **下载整个清单（含补漏）**：清掉范围，跑完整清单；已下载的照样自动跳过，张数不足的会补跑。
- 底层其实是三段既有能力被接起来了：下载脚本本身就按台账跳过已完成项（张数不足的补跑）、
  `preview::load` 已给每条标了 `downloaded`、`_next_run.json` 是既有的「下一轮范围」机制。
- **顺手修掉一个真 bug**：`_next_run.json` 以前只有「结果查看 → 设为下一轮下载」会写，
  但 `pipeline.mjs` 从不读它（界面却写着「下一轮只下载指定的 N 条」）——也就是说那个按钮
  实际上没生效。现在流水线在没给 `--selected` 时自动采用该文件，并在标题里写明
  「指定批次 / 整个清单」。
- 真假数据都验过：`--check-new` 诊断对三个平台的库各跑一次；流水线在有/无 `_next_run.json`
  两种情况下打出的命令不同（见审查报告 §7.6）。

### 更新：下载并安装 + 一条命令发布

- **「下载并安装」按钮**：`install_update` 命令（下载 → 验签 → 替换 App → 自动重启），界面上带二次确认（再点一次才执行）。签名不通过会在下载阶段就报错，不会把没验过的包装上去。
- **`tools/dist/publish_update.sh`**：生成清单 → 本地验签 → 上传（`--upload` 里写任意 scp/rsync/aws 命令）→ 拉回远端清单与本地比对，避免「只传了包没传清单」「清单还是旧版本」。
- **真实 https 端到端实测**：用 Cloudflare 临时隧道把「正式构建（严格配置，不认 http、不认自签证书）」接上公网 https——发现 0.3.2 → 下载 2,920,259 字节 → 验签通过 → **真的替换了 App**（副本版本 0.3.1 → 0.3.2，dist 未受影响）。另测：把更新包改一个字节 → `signature verification failed`；版本相同 → 已是最新版本。
- 实测中发现的正常行为：updater 拒绝从含符号链接的路径启动（`/tmp` → `/private/tmp`），报 `StartingBinary found current_exe() that contains a symlink`；App 装在普通目录（如 /Applications）即可。
- **默认关闭更新检查**：`plugins.updater.endpoints` 留空；此时点「检查更新」会明确说「还没有配置更新地址」，而不是拿占位域名去撞网络（单机自用即为此状态，新版本双击 DMG 覆盖安装即可）。
- 仍未完成：长期托管地址（需要你自己的域名/对象存储，用 publish_update.sh 一条命令发布即可；界面上也能临时填地址先试）。
